# QRKot

Благотворительный фонд поддержки котиков. Сервис принимает пожертвования и сам направляет их в открытые целевые проекты: на корм, лечение, приюты и другие задачи.

Пользователь жертвует деньги фонду, а не выбирает проект. Приложение вкладывает сумму в самый старый проект, который ещё не собрал нужную сумму. Если денег больше, чем не хватает проекту, проект закрывается, а остаток переходит к следующему по дате открытия. Если открытых проектов нет, остаток ждёт и автоматически вкладывается в новый проект в момент его создания.

## Возможности

- регистрация, вход по JWT и профиль пользователя;
- целевые проекты: список, создание, изменение и удаление (создание и изменение доступны суперпользователю);
- пожертвования с необязательным комментарием;
- автоматическое распределение средств между проектами в одной транзакции.

Проект закрывается, когда собранная сумма достигает требуемой: выставляются `fully_invested` и `close_date`. То же происходит с пожертвованием, когда вся его сумма распределена.

Удалить можно только проект, в который ещё не поступали деньги. Закрытый проект нельзя редактировать, а требуемую сумму нельзя сделать меньше уже собранной.

## Стек

Python, FastAPI, Pydantic, SQLAlchemy (async), SQLite, Alembic, fastapi-users.

## Структура

```
app/
  main.py              приложение и описание Swagger
  api/                 роутеры, эндпоинты, зависимости и валидаторы
  core/                настройки, сессия БД, пользователи
  models/              CharityProject, Donation и общий абстрактный класс
  schemas/             схемы запросов и ответов
  crud/                операции с базой
  services/            распределение пожертвований
alembic/               миграции
tests/                 проверки API
```

Общие поля проектов и пожертвований (`full_amount`, `invested_amount`, `fully_invested`, `create_date`, `close_date`) живут в абстрактной модели `InvestmentBase`. Отдельной таблицы у неё нет.

## Запуск

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
alembic upgrade head
python setup_for_postman.py
uvicorn app.main:app --reload
```

По умолчанию база — файл `fastapi.db` в корне проекта (`sqlite+aiosqlite:///./fastapi.db`). Адрес и секрет JWT можно переопределить переменными `DATABASE_URL` и `SECRET`.

Скрипт `setup_for_postman.py` создаёт суперпользователя:

- email: `root@admin.ru`
- password: `root`

Повторный запуск скрипта на той же базе завершится ошибкой: пользователь уже есть.

Swagger: <http://127.0.0.1:8000/docs>

## API

| Метод | Путь | Кто может вызвать |
| --- | --- | --- |
| POST | `/auth/register` | любой посетитель |
| POST | `/auth/jwt/login` | любой посетитель |
| POST | `/auth/jwt/logout` | авторизованный пользователь |
| GET, PATCH | `/users/me` | авторизованный пользователь |
| GET, PATCH | `/users/{id}` | суперпользователь |
| GET | `/charity_project/` | любой посетитель |
| POST | `/charity_project/` | суперпользователь |
| PATCH, DELETE | `/charity_project/{id}` | суперпользователь |
| POST | `/donation/` | авторизованный пользователь |
| GET | `/donation/my` | авторизованный пользователь |
| GET | `/donation/` | суперпользователь |

Удаление пользователей и изменение уже созданных пожертвований не предусмотрены.

## Подготовка перед запуском коллекции в Postman
Копию нужно сделать после подготовки и до первого запуска коллекции. К этому моменту в базе должен быть только суперпользователь root@admin.ru, без проектов и пожертвований.
copy fastapi.db fastapi.db.bak
Перед повторным запуском коллекции верните этот файл на место:
copy /Y fastapi.db.bak fastapi.db
Если коллекция уже отработала, текущий fastapi.db для копии не подходит: в нём остались созданные проекты и пожертвования. Тогда удалите файл, заново выполните alembic upgrade head и python setup_for_postman.py, и уже этот чистый файл сохраните как копию.
